# 0002 节点状态模型

## 决策

### 状态归属

| 状态 | 适用角色 | 来源 | 重启后 |
|---|---|---|---|
| 角色 | 全部 | 用户设置 | 恢复 |
| 正向风向 | 全部 | 用户设置 | 恢复 |
| 风向模式 | 主、独立 | 用户设置 | 恢复 |
| 往复周期 | 主、独立 | 用户设置 | 恢复 |
| 风力 | 主、独立 | 用户设置 | 恢复 |
| 风力 | 从 | 主节点同步 | 不保存，上电为关闭 |
| 当前风向（正向或反向） | 主、独立 | 由风向模式和往复周期推算 | 不保存，由风向模式重新决定 |
| 当前风向（正向或反向） | 从 | 主节点同步 | 不保存，上电静止 |
| 多主警告 | 主 | 收到他人的同步消息时置位，用户清除 | 不保存，重启后消失 |

从节点保留最后保存的风向模式和往复周期，重启后恢复，在从节点上不起作用。

只在用户修改设置时写入持久化存储。当前风向是运行时状态，不写入。

### 同步

- 只有主节点发送同步消息，内容是目标状态：当前风向（正向或反向，不含进气或排气）和风力。消息里带发送者标识。
- 从节点收到同步消息就直接应用，不检查来源，不检查先后顺序，不做超时。收不到消息时保持最后状态。
- 从节点按自己的正向风向设置，把收到的正向或反向换算成实际风向。
- 主节点按固定周期（5 秒）发送。风向翻转、用户修改风力、角色切换为主时，立即多发一次，不连发。主节点风扇关闭时照常按周期发送，风力为关闭，风向继续按往复周期推算。
- 从、独立节点不发送。独立节点不接收同步消息。
- 主节点收到发送者标识不是自己的同步消息，就置多主警告，由用户清除。

### 上电

- 从节点上电后保持静止（风扇停转，实际风向为停止），直到收到第一条同步消息。
- 主节点和独立节点上电后恢复保存的设置和风力。固定模式的风向按模式设定；往复模式从正向开始。

### 角色切换

切换立即生效。新角色需要而无法确定的值，沿用当前值。

## 依据

- 角色定义与切换：[F-003](../prd.md#f-003)、[F-010](../prd.md#f-010)。
- 正向风向对所有角色有效：[F-004](../prd.md#f-004)。
- 风向模式、往复周期、风力只由主、独立节点设定：[F-005](../prd.md#f-005)、[F-006](../prd.md#f-006)、[F-007](../prd.md#f-007)。
- 从节点只跟随风向和风力，不跟随模式和周期：[F-008](../prd.md#f-008)。
- 失联保持与重启恢复：[F-009](../prd.md#f-009)。
- 多主警告：[F-011](../prd.md#f-011)。
- 本地网络运行，同步不依赖外部服务：[F-001](../prd.md#f-001)。
- 同步消息可能丢失，目标状态是完整快照，周期重发即可修复丢失，不需要确认和重传。
- 从节点只需要知道风向和风力就能执行，模式和周期只用于主节点决定何时翻转，翻转结果已体现在当前风向里。
- 往复模式下风向每个周期翻转一次，写入持久化存储会快速磨损闪存。

## 备选方案

### 广播相位基准，从节点本地计时翻转（未采纳）

主节点离线后从节点仍能继续往复。但各节点时钟漂移，相位会逐渐偏离，而且与「失联后保持当前状态」的要求不符。

### 广播翻转事件（未采纳）

事件丢失后无法自行恢复，需要确认与重传机制，状态快照则天然幂等。

### 带序号，只接受更大的序号（未采纳）

从节点不需要判断顺序，多主检测靠发送者标识即可。局域网内乱序罕见，即使发生，旧消息最多让状态短暂回退，下一个周期就会纠正。序号还带来回绕和对方重启归零后被长期拒收的问题。

### 风向翻转时连发多次（未采纳）

可以缩短丢包后的同步延迟，但 PRD 不约定同步时延，连发增加空口占用和功耗。原型测试发现翻转明显不同步时再考虑。

### 同步风向模式和往复周期（未采纳）

从节点用不到，只增加报文内容。

### 持久化当前风向（未采纳）

闪存磨损，且重启后风向由风向模式重新决定即可。

### 从节点上电恢复断电前的状态（未采纳）

可能按过期状态运转，而主节点的状态可能已经改变。

## 影响

- 从节点的风向翻转晚于主节点，最多晚一个发送周期（丢包时更久）。
- 主节点离线时，从节点停在最后的风向和风力，不会继续往复。
- 从节点重启时若主节点离线，从节点保持静止，直到主节点恢复。
- 局域网内有两个主节点时，从节点会在两者的风向之间来回跳变，系统不处理。
- 主节点靠发送者标识排除自己发出的消息。ESP32 的网络栈不回环自己发出的组播，但其他网络栈可能回环。
- 每 5 秒发送一次的耗电和网络开销，需要原型验证。
- 角色切换为主时，风向模式和往复周期是该节点最后保存的值，从节点期间没有保存过的，是默认值。
